# US16 - Email and app reminders
Source: workspace US16. Branch: feature/US16-meeting-reminder-backend.

Uses shared meeting/user/meeting_participant entities and the singular notification table from ERD.
Notification delivery adds recipient_email, lead_minutes, retry timestamps/count and error_message.
POST /api/meetings/{id}/reminders accepts {userId,minutesBefore,channel: EMAIL|APP, optional email}.
Only the organizer can schedule reminders for active members; email must match registered user data.
GET on that path returns only the authenticated member's own notifications.
POST /api/reminders/dispatch is an Admin operation.

The scheduler automatically queues email and app reminders 15 minutes before future active meetings.
It also catches reminders that became due while the backend was offline.
Rescheduled/cancelled meetings and declined/removed/inactive users invalidate outstanding reminders.
Unique rows prevent duplicate queueing. SMTP failures retry with backoff and do not reset on each scan.
Set SMTP_HOST/PORT/USERNAME/PASSWORD/AUTH/STARTTLS and MAIL_FROM through environment variables.
REMINDER_ENABLED defaults to true; set false for tests or to disable periodic delivery.
Feature properties are isolated in application-us16.properties. Existing meeting/participant routes are preserved.
