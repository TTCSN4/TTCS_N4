# US28 - HRM / ERP integration
Source: workspace US28. Branch: feature/US28-hrm-erp-integration-backend.

Shared ERD user/role/department entities are reused. Audit records use the extension table hrm_sync_runs.
Endpoints are under /api/integrations/hrm: /pull, /webhook, /sync, /status, /history, /users, /departments.
Webhook and sync require X-Integration-Key matching HRM_WEBHOOK_KEY. Pull, status and history require authenticated Admin.
An empty webhook key refuses writes. Pull/scheduled sync are disabled by default.
Set HRM_INTEGRATION_ENABLED, HRM_BASE_URL, HRM_API_KEY and HRM_WEBHOOK_KEY through environment variables.
Payload: departments[{hrmCode,name}], employees[{hrmCode,fullName,email,phone,departmentHrmCode,status,roleCode}],
fullSnapshot, source, sourceUpdatedAt. An empty employee list is allowed for a complete empty snapshot.
roleCode must refer to an existing project role ID (default ATTENDEE). No demo roles/users are inserted on startup.
Department/employee codes and email are normalized. Snapshot synchronization is transactional;
complete snapshots deactivate missing HRM employees, partial snapshots leave them unchanged. Failures are audited.
LocalDateTime uses the project's Asia/Ho_Chi_Minh convention.

For an existing MySQL ERD database, apply database/backend/US28_hrm_sync_audit.sql once before using Hibernate validate.
